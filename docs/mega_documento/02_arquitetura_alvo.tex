\section{Visão Geral da Arquitetura de Software e o Padrão ``Fluxo por Aba''}

A construção de um sistema de recomendação corporativo escalável e sustentável exige que os princípios de engenharia de software caminhem em estrita conformidade com a modelagem de \textit{Machine Learning}. Empregando a metodologia \textbf{TDSP (\textit{Team Data Science Process})}, a solução desenvolvida neste projeto supera o paradigma de scripts analíticos monolíticos e isolados em \textit{Jupyter Notebooks}, consolidando-se como um software com arquitetura desacoplada, modularizada e totalmente conteinerizada.

A aplicação adota um modelo arquitetural estrito em \textbf{3 Camadas Lógicas}, estabelecendo fronteiras bem delineadas entre interface de usuário, computação algorítmica e persistência de dados:

\begin{enumerate}
    \item \textbf{Camada de Apresentação (Frontend Reativo):} Implementada com o framework Streamlit (\texttt{app/dashboard.py}), sendo responsável pela renderização visual, orquestração de abas, captura de interações do usuário e exibição de componentes explicativos.
    \item \textbf{Camada de Lógica e Modelos de Machine Learning (\texttt{src/}):} Concentra a inteligência do sistema, encapsulando os motores de recomendação por conteúdo (\texttt{RecSysCBF}), colaborativo baseado em SVD (\texttt{RecSysCF}) e os algoritmos estatísticos de diagnóstico de mercado (\texttt{gerar\_figuras\_eda.py}).
    \item \textbf{Camada de Armazenamento, Cache e Dados (\texttt{data/}):} Gerencia os dados brutos (\texttt{data/raw/}), dados processados (\texttt{data/processed/}), artefatos serializados de modelos treinados (\texttt{.pkl}) e a infraestrutura de cache de alta performance em memória RAM (\texttt{@st.cache\_resource} e \texttt{@st.cache\_data}).
\end{enumerate}

\subsection{O Conceito de ``Fluxo por Aba'' como Microssistemas Independentes}

O framework Streamlit adota uma semântica de execução puramente reativa: a cada modificação em um componente de interface (\textit{widget}), como o deslocamento de um seletor numérico (\textit{slider}) ou a marcação de uma caixa de seleção (\textit{checkbox}), o arquivo principal \texttt{app/dashboard.py} é inteiramente reexecutado do topo à base (\textit{rerun}).

Para evitar acoplamentos colaterais e sobrecargas computacionais decorrentes desse comportamento reativo, o projeto formaliza o padrão de \textbf{Fluxo por Aba}: \textbf{cada aba do sistema atua como um microssistema independente}. Em termos práticos de engenharia, cada aba possui um ciclo de vida computacional autocontido:
\begin{enumerate}
    \item \textbf{Entrada de Parâmetros:} Captura e isolamento do estado específico dos \textit{widgets} da aba ativa;
    \item \textbf{Computação e Transformação:} Disparo de rotinas algorítmicas exclusivas daquela funcionalidade, sem propagação de efeitos colaterais para abas vizinhas;
    \item \textbf{Renderização Visual:} Exibição independente de relatórios tabulares, figuras interativas e métricas de desempenho.
\end{enumerate}

Essa abordagem confere elevada estabilidade e manutenibilidade a longo prazo, permitindo que aprimoramentos pontuais em um recomendador (por exemplo, a alteração no número de fatores latentes do SVD) sejam conduzidos de forma estritamente isolada, garantindo a integridade dos demais subsistemas.

\section{Os 5 Componentes Estruturais Obrigatórios de Cada Aba}

Com o intuito de estabelecer uniformidade técnica e consistência epistemológica em todo o ciclo de vida do projeto, a especificação e implementação de cada aba obedecem rigorosamente a \textbf{5 componentes estruturais obrigatórios}:

\begin{enumerate}[label=\textbf{\arabic*.}]
    \item \textbf{Objetivo de Negócio \& User Story Vinculada:} Define a tese mercadológica ou a necessidade analítica atendida pela funcionalidade, delimitando a persona de negócio destinatária (Candidato, Recrutador Corporativo ou Avaliador Técnico).
    \item \textbf{Entrada de Dados (Inputs e Artefatos de Base):} Identifica os conjuntos de dados utilizados (arquivos brutos \texttt{.csv}, arquivos colunares \texttt{.parquet} ou matrizes serializadas \texttt{.pkl}) e os hiperparâmetros manipuláveis na interface pelo usuário em tempo de execução.
    \item \textbf{Processamento / Pipeline Algorítmico:} Detalha formalmente o fluxo matemático e analítico executado nos bastidores (formulações de TF-IDF, similaridade vetorial, fatoração matricial por valores singulares e agregações estatísticas).
    \item \textbf{Saída Visual (Outputs e Elementos de Decisão):} Especifica os componentes renderizados em tela, tais como tabelas ranqueadas Top-$N$, indicadores em formato de cartão (\textit{KPI cards}), figuras gráficas e painéis sanfonados de explicabilidade algorítmica.
    \item \textbf{Comportamento sob Limitações, Fallback e Transição:} Estabelece as salvaguardas computacionais para tratamento de exceções (como o problema de inicialização a frio, ou \textit{Cold Start}), além de orientar o usuário para o próximo estágio metodológico do fluxo.
\end{enumerate}

\subsection{Aba 1: Visão de Negócio (EDA de Mercado)}

\begin{tcolorbox}[userstorybox, title={User Story Vinculada (Aba 1)}]
\textit{``Como candidato, quero ver estatísticas do mercado de vagas, para entender o contexto antes de buscar recomendações.''} (\textbf{Persona:} Candidato).
\end{tcolorbox}

\begin{enumerate}[label=\textbf{\arabic*.}]
    \item \textbf{Objetivo de Negócio:} Apresentar o diagnóstico quantitativo do mercado de trabalho em tecnologia a partir de dados empíricos, validando hipóteses mercadológicas estratégicas para orientar o desenho dos modelos de recomendação subsequentes.
    \item \textbf{Entradas de Dados \& Artefatos:}
    \begin{itemize}
        \item \texttt{data/raw/postings.csv}: Base primária contendo 123.849 anúncios de empregos coletados entre 2023 e 2024;
        \item \texttt{data/raw/companies/companies.csv}: Metadados cadastrais e segmentação de porte corporativo.
    \end{itemize}
    \item \textbf{Processamento \& Algoritmos (\texttt{src/gerar\_figuras\_eda.py}):}
    \begin{itemize}
        \item Rotinas de higienização de dados, imputação de valores ausentes e saneamento de valores atípicos (\textit{outliers}) de remuneração;
        \item Mensuração da mediana de taxa de conversão (\textit{Click-Through Rate} -- CTR), definida pela razão entre candidaturas efetivas e visualizações:
        \begin{equation}
            \text{CTR} = \frac{\text{applies}}{\text{views}}
        \end{equation}
        \item Avaliação empírica de 5 hipóteses estratégicas (mantendo rigor epistêmico quanto à distinção entre correlação e causalidade):
        \begin{itemize}
            \item \textbf{Hipótese 1 ($H_1$ -- Preferência Remota): Confirmada.} Vagas remotas apresentam CTR mediano de 20,6\% contra 16,5\% das vagas presenciais (vantagem observada de +24,5\% em atratividade).
            \item \textbf{Hipótese 2 ($H_2$ -- Disparidade por Senioridade): Confirmada.} O salário médio anual apresenta forte correlação positiva com a senioridade (\$118k para profissionais sêniores contra \$58k para posições de entrada).
            \item \textbf{Hipótese 3 ($H_3$ -- Remoto vs. Presencial): Refutada.} O senso comum mercadológico supunha maior remuneração no presencial para compensação de deslocamento; os dados mostram remuneração média remota 45\% superior.
            \item \textbf{Hipótese 4 ($H_4$ -- Salário por Porte de Empresa): Refutada.} Médias empresas e \textit{startups} tecnológicas registraram salários médios superiores aos de grandes corporações tradicionais na base avaliada.
            \item \textbf{Hipótese 5 ($H_5$ -- Transparência Salarial): Confirmada.} Vagas remotas e posições de média/alta maturidade exibem maior índice de publicação aberta de faixas salariais.
        \end{itemize}
    \end{itemize}
    \item \textbf{Saída Visual (Outputs):} Cartões diagnósticos com o resultado de cada hipótese e justificativas metodológicas, fornecendo a sustentação teórica para a criação do bônus empírico de atratividade mercadológica utilizado na filtragem por conteúdo.
    \item \textbf{Fallback e Transição:} Operação independente de histórico de usuário. Caso os dados brutos estejam ausentes, uma mensagem orienta o usuário a executar a rotina de automação via \texttt{Makefile}. A aba serve de base contextual para que o candidato transite para a Aba 2 e configure seu perfil de competências.
\end{enumerate}

\subsection{Aba 2: Simulador CBF (Filtragem Baseada em Conteúdo)}

\begin{tcolorbox}[userstorybox, title={User Story Vinculada (Aba 2)}]
\textit{``Como candidato sem histórico ou em transição, quero buscar vagas por palavras-chave e habilidades pontuais, para obter recomendações semanticamente aderentes sem depender de dados prévios.''} (\textbf{Persona:} Candidato).
\end{tcolorbox}

\begin{enumerate}[label=\textbf{\arabic*.}]
    \item \textbf{Objetivo de Negócio:} Permitir ao usuário sintetizar interativamente um perfil profissional dinâmico (combinando preferências explícitas, rejeições e habilidades textuais livres), gerando recomendações semanticamente compatíveis mesmo na completa ausência de histórico pretérito de navegação.
    \item \textbf{Entradas de Dados \& Parâmetros na UI:}
    \begin{itemize}
        \item Amostra estratificada de 25.000 anúncios de vagas oriunda de \texttt{postings.csv}, delimitada para otimização de latência e consumo de memória RAM;
        \item Parâmetros dinâmicos manipulados pelo candidato na interface:
        \begin{itemize}
            \item Vagas de interesse selecionadas (vetor de reforço positivo);
            \item Vagas rejeitadas selecionadas (vetor de penalização negativa);
            \item Campo de texto livre para inserção de competências (\texttt{custom\_skills});
            \item Filtro booleano exclusivo para vagas em modalidade remota;
            \item Controle deslizante para quantidade de recomendações Top-$N \in [5, 20]$.
        \end{itemize}
    \end{itemize}
    \item \textbf{Processamento \& Algoritmos (\texttt{src/recomendador.py}):}
    \begin{enumerate}[label=\alph*)]
        \item \textbf{Construção do Documento Textual por Item ($d_j$):} Concatenação ponderada dos atributos da vaga com dobro de peso atribuído ao título da função:
        \begin{equation}
            \text{Documento}_j = (\text{Título}_j \times 2) \oplus \text{Skills}_j \oplus \text{Nível\_Experiência}_j
        \end{equation}
        \item \textbf{Vetorização Esparsa via TF-IDF:} Mapeamento dos documentos em um espaço vetorial composto pelos 3.000 termos mais relevantes segundo a frequência inversa do documento.
        \item \textbf{Síntese do Vetor de Perfil do Usuário ($\mathbf{u}$):} Construção de um vetor híbrido combinando centróides positivos, negativos e termos textuais digitados:
        \begin{equation}
            \mathbf{u} = \alpha \cdot \mathbf{v}_{\text{curtidas}} - \beta \cdot \mathbf{v}_{\text{rejeitadas}} + \gamma \cdot \mathbf{v}_{\text{skills}}
        \end{equation}
        onde adotou-se a calibração unitária balanceada $\alpha = 1{,}0$, $\beta = 1{,}0$ e $\gamma = 1{,}0$.
        \item \textbf{Similaridade do Cosseno:} Avaliação da aderência semântica entre o perfil sintetizado $\mathbf{u}$ e cada documento de vaga $\mathbf{d}_j$:
        \begin{equation}
            \cos(\mathbf{u}, \mathbf{d}_j) = \frac{\mathbf{u} \cdot \mathbf{d}_j}{\|\mathbf{u}\| \|\mathbf{d}_j\|}
        \end{equation}
        \item \textbf{Bônus Empírico de Atratividade (CTR):} Incorporação do engajamento de mercado validado na Aba 1 para favorecer oportunidades com maior conversão histórica comprovada:
        \begin{equation}
            \text{Score Final}_j = \cos(\mathbf{u}, \mathbf{d}_j) + 0{,}05 \cdot \text{CTR}_j
        \end{equation}
    \end{enumerate}
    \item \textbf{Saída Visual (Outputs):} Tabela interativa com o ranking ordenado Top-$N$, expondo colunas informativas de Título, Empresa, Nível de Experiência, Selo Remoto, Similaridade do Cosseno e Bônus de CTR aplicado.
    \item \textbf{Fallback e Resolução de Limitações:}
    \begin{itemize}
        \item \textbf{Resolução Nativa de Cold Start:} Como o modelo baseia-se puramente em atributos do item e do texto digitado, a inserção de uma única habilidade (ex.: ``Python'') é suficiente para gerar recomendações coerentes, eliminando a dependência de um histórico prévio de interações;
        \item Validação defensiva na interface: caso nenhum critério de busca seja fornecido, o sistema exibe alerta amigável de orientação sem interrupção de execução.
    \end{itemize}
\end{enumerate}

\subsection{Aba 3: Filtragem Colaborativa (SVD sobre Dados Sintéticos)}

\begin{tcolorbox}[userstorybox, title={User Story Vinculada (Aba 3)}]
\textit{``Como plataforma/recrutador, quero aprender padrões implícitos de candidatura a partir do histórico coletivo, para sugerir oportunidades alinhadas ao comportamento de profissionais similares.''} (\textbf{Persona:} Plataforma / Recrutador).
\end{tcolorbox}

\begin{enumerate}[label=\textbf{\arabic*.}]
    \item \textbf{Objetivo de Negócio:} Demonstrar a eficácia de algoritmos baseados em fatores latentes na captura de padrões complexos de comportamento coletivo, oferecendo auditoria detalhada por meio de explicabilidade matemática aditiva, em conformidade com as diretrizes de transparência algorítmica da LGPD (Lei nº 13.709/2018).
    \item \textbf{Entradas de Dados \& Artefatos:}
    \begin{itemize}
        \item \texttt{modelo\_svd.pkl}: Modelo de Decomposição em Valores Singulares (\textit{Singular Value Decomposition}) treinado e serializado;
        \item \texttt{data/processed/catalogo\_cf.csv}: Catálogo padronizado de 6.000 vagas indexadas com títulos e metadados;
        \item \texttt{data/processed/interacoes.parquet}: Matriz contendo 602.216 avaliações explícitas (escala de 1 a 5) atribuídas por 5.000 personas sintéticas estruturadas;
        \item Controles de interface: Seletor de identificador de usuário sintético ($u \in [1, 5000]$), opção para excluir vagas já avaliadas, filtro de modalidade remota e seletor Top-$N$.
    \end{itemize}
    \item \textbf{Processamento \& Algoritmos (\texttt{src/filtragem\_colaborativa.py}):}
    \begin{enumerate}[label=\alph*)]
        \item Recuperação do vetor latente do usuário selecionado $p_u \in \mathbb{R}^{20}$ e mapeamento de sua persona primária;
        \item Carregamento do histórico real de treino do usuário a partir do arquivo colunar parquet;
        \item Cálculo da nota prevista $\hat{y}_{u,i}$ para cada vaga $i$ do catálogo não avaliada previamente pelo usuário:
        \begin{equation}
            \hat{y}_{u,i} = \mu + b_u + b_i + q_i^T p_u
        \end{equation}
        onde:
        \begin{itemize}
            \item $\mu = 3{,}230$ representa a média global de todas as avaliações no conjunto de treino;
            \item $b_u \in \mathbb{R}$ corresponde ao viés específico do usuário $u$ (tendência individual a ser mais leniente ou rigoroso nas notas);
            \item $b_i \in \mathbb{R}$ expressa o viés do item $i$ (atratividade geral da vaga frente ao conjunto dos candidatos);
            \item $q_i^T p_u$ traduz o produto interno dos fatores latentes de dimensão $k=20$, mensurando a interação específica entre as afinidades do usuário e as características intrínsecas da vaga.
        \end{itemize}
        \item Ordenação decrescente pelas notas estimadas e filtragem de corte Top-$N$.
    \end{enumerate}
    \item \textbf{Saída Visual (Outputs):}
    \begin{itemize}
        \item Gráfico de barras ilustrando a distribuição de afinidade do usuário entre as 5 personas de referência (\textit{Tech, Business, Design, Saúde, Operações});
        \item Tabela de histórico de avaliações passadas para confronto com as novas predições;
        \item Tabela Top-$N$ com predições numéricas no intervalo $[1{,}00; 5{,}00]$;
        \item \textbf{Expander de Explicabilidade Aditiva:} Tabela transparente que decompõe a nota exata prevista pelo SVD em suas quatro parcelas constitutivas ($\mu, b_u, b_i, q_i^T p_u$), cumprindo o princípio legal da explicabilidade.
    \end{itemize}
    \item \textbf{Fallback e Limitações:}
    \begin{itemize}
        \item \textbf{Resiliência à Esparsidade Extrema (97,99\%):} A projeção em 20 fatores latentes permite ao SVD estimar afinidades para qualquer par $(u, i)$. Isso supera decisivamente os métodos baseados em memória (como o KNN \textit{user-based}), que falharam em 32,4\% das consultas devido à ausência de vizinhos em comum na matriz esparsa;
        \item \textbf{Limitação de Cold Start Puro:} O algoritmo não é capaz de gerar inferências para usuários fora do conjunto de treino sem histórico prévio, delegando esse cenário ao motor de conteúdo da Aba 2 ou ao motor híbrido.
    \end{itemize}
\end{enumerate}

\section{O Salto Arquitetural: Evolução para o Motor Híbrido (Fase 3)}

\subsection{Estratégias de Hibridização segundo Robin Burke (2002)}

Para superar simultaneamente o risco de \textit{Cold Start} da filtragem colaborativa e a falta de novidade (\textit{serendipity}) da filtragem por conteúdo, o sistema implementa duas estratégias fundamentadas na taxonomia clássica de Robin Burke \cite{burke2002}:

\begin{tcolorbox}[burkebox, title={Modelo Híbrido Proposto (Robin Burke, 2002)}]
\textbf{1. Estratégia Ponderada (\textit{Weighted}):}
\begin{equation}
\text{Score Final}_{u,j} = w_1 \cdot \text{Score}_{\text{CBF}}^{\text{norm}}(u, j) + w_2 \cdot \text{Score}_{\text{CF}}^{\text{norm}}(u, j)
\end{equation}
\begin{itemize}
    \item Fusão linear de pontuações de origens distintas previamente normalizadas no intervalo $[0, 1]$.
    \item Calibração empírica dos pesos: $w_1 = 0{,}40$ (preservação semântica das competências) e $w_2 = 0{,}60$ (captura do comportamento coletivo).
\end{itemize}
\vspace{0.2cm}
\textbf{2. Estratégia de Chaveamento Dinâmico (\textit{Switching}):}
\begin{equation}
\text{Modo de Operação}(u) = 
\begin{cases} 
\text{CBF (Conteúdo Exclusivo)}, & \text{se } |I_u| = 0 \text{ (Novo Usuário)}, \\
\text{Fusão Ponderada (CBF} + \text{CF)}, & \text{se } |I_u| > 0 \text{ (Usuário com Histórico)},
\end{cases}
\end{equation}
onde $|I_u|$ denota a quantidade de interações históricas registradas para o usuário $u$.
\end{tcolorbox}

\subsection{Camada de Cache de Alta Performance em Memória RAM}

Para contornar o gargalo de reexecução integral do script Streamlit a cada evento de interface e garantir \textbf{tempos de resposta inferiores a um segundo}, adotou-se o gerenciamento de cache nativo em memória:
\begin{enumerate}
    \item \textbf{\texttt{@st.cache\_resource} (Instanciação de Motores Pesados):} Aplicado nas rotinas \texttt{load\_cbf\_model()} e \texttt{load\_cf\_model()} em \texttt{app/dashboard.py}. Garante que os modelos e matrizes esparsas sejam carregados uma única vez na inicialização, mantendo ponteiros compartilhados em memória RAM;
    \item \textbf{\texttt{@st.cache\_data} (Leitura de Dados Tabulares):} Aplicado na leitura de catálogos e métricas serializadas, evitando releituras lentas de disco;
    \item \textbf{Amostragem Otimizada de Segurança:} Redução amostral do universo de 123k vagas para 25k registros no CBF, preservando riqueza semântica e prevenindo estouro de memória (\textit{Out-Of-Memory} -- OOM) em ambientes com recursos moderados.
\end{enumerate}
